# BLOCKWORLD 中文手册

版本 0.3.1 ｜ 2026-11-18 ｜ MIT 许可 ｜ https://github.com/Xbotsd/blockworld

## 0. 一页速览

| 项目 | 内容 |
|---|---|
| 它是什么 | 区块化的"地质—生态—机器人"闭环沙盘：给定场地与干预，判断可行性判据会不会翻转，并用实测数据持续修正结论 |
| 它不是什么 | 不是场地预测工具，不替代勘察，不做动力时程、固结、液化分析 |
| 核心问题 | 换掉这个成分，结论会不会变；接上机器人后，实测数据会不会改变结论 |
| 依赖 | Python 3.10+、numpy、Pillow；离线模型可选（Ollama 或 OpenAI 兼容端点） |
| 四条命令 | `blockworld template` / `study` / `robot` / `agent` |
| 测试规模 | 113 项，覆盖公式对照、数据契约、拒绝行为、闭环收敛 |

## 1. 安装

标准安装：

```bash
git clone https://github.com/Xbotsd/blockworld.git
cd blockworld
pip install -e .
blockworld --help
```

离线机器（没有 PyPI 访问）直接原地运行，不需要安装：

```powershell
$env:PYTHONPATH="src"; python -m blockworld --help
```

依赖只有两个纯 Python 包，若连 pip 也没有，把 `src/` 加入路径即可，其余全部是标准库。

## 2. 十分钟跑通

四步，每步都有产出，可以只跑你关心的那一步。

```bash
blockworld template data/site                              # 1. 数据模板
blockworld study examples/study_landing.json --out out_study --mc 60 --morris 6
blockworld robot --out out_robot --ticks 12                # 2. 机器人闭环
blockworld agent --out out_agent --backend none            # 3. 离线顾问（先不接模型）
blockworld demo  --out out --years 55                      # 4. 全流程图文报告
```

对应产出：

| 命令 | 主要文件 | 用途 |
|---|---|---|
| `template` | `data/site/site.json` + 4 个 CSV | 换成你的实测数据 |
| `study` | `study.json` / `montecarlo.json` / `morris.json` | 方案比较与不确定性 |
| `robot` | `robot_report.json` | 闭环判定与逐 tick 轨迹 |
| `agent` | `agent_brief.md` / `agent_advice.json` | 可归档的现场简报 |
| `demo` | `report.html` / `sandbox.png` / `summary.json` | 交互沙盘与对比图 |

## 4. 数据契约

### 4.1 `site.json`

```json
{
  "grid": {"nx": 24, "ny": 24, "cell": 100, "x0": 0, "y0": 0},
  "gravity": 9.81,
  "seed": 1,
  "elevation": {"csv": "dem.csv"},
  "temp":      {"csv": "temp.csv"},
  "precip":    {"csv": "precip.csv"},
  "boreholes": {"csv": "boreholes.csv"},
  "provenance": {"source": "2025 年某场地勘察"}
}
```

字段含义：

| 字段 | 说明 |
|---|---|
| `grid.nx / ny` | x、y 方向的区块数 |
| `grid.cell` | 区块边长，米 |
| `elevation` | 数字矩阵或 `{"csv": 文件名}`，ny 行 × nx 列 |
| `temp` / `precip` | 年均温 °C、年降水 mm，可省略（省略时用常数并标记） |
| `boreholes` | 钻孔表或内存定义 |
| `provenance.source` | 会原样进入结果与报告，请如实填写 |

### 4.2 三个 CSV

纯数值矩阵，逗号分隔，ny 行 × nx 列，允许一行表头。单位：米 / °C / 毫米每年。

### 4.3 钻孔 CSV

```csv
x,y,ground,top,bottom,material,source
200,200,20,0,1,silt,survey
200,200,20,1,4,clay_soft,survey
200,200,20,4,9,sand_dense,survey
```

规则：同一 `(x, y)` 的区间必须从 0 连续铺到底，出现缺口或重叠会报出具体深度；
`material` 必须是材料库里的 key。

### 4.4 新增材料

```python
from blockworld import materials

materials.LIBRARY["my_silt"] = materials.Material(
    key="my_silt", name="场地粉土",
    gamma=18.6, c=9.0, phi=27.0, E=14.0, nu=0.32, k=2e-6,
    models=("mohr-coulomb", "hardening-soil"),
    source="BH-03，2025",
)
```

每种材料自带有效域（`phi_max`、`c_max`、`gamma_min/max`），越界的替换会被拒绝而不是截断。

### 4.5 会被拒绝的输入

| 情况 | 结果 |
|---|---|
| 缺 DEM 或缺钻孔 | `ValueError: 缺少 DEM 高程` |
| 数组形状与网格不符 | `ValueError`，同时报出两个形状 |
| 钻孔区间有缺口 | `SiteFormatError`，报出缺失深度 |
| 未知材料 key | `SiteFormatError`，列出可用 key |
| 降水 ≤ 0、重力越界 | `ValueError` |

## 5. 研究接口（Study）

```python
from blockworld import Criteria, Intervention, Region, Study
from blockworld.io import load_site

study = Study(
    site=load_site("data/site/site.json"),
    criteria=Criteria(
        purposes=("infrastructure", "landing"),
        foundation=Foundation(B=1.5, L=1.5, D=1.5, load_kN=400),
        landing_site=Region.circle(600, 300, 150),
    ),
    interventions=(
        Intervention("换填 6 m 砂砾", [
            {"op": "material", "material": "gravel_dense",
             "top_depth": 0, "bottom_depth": 6, "region": {"kind": "all"}}]),
    ),
)
result = study.run()
result.passed()   # 每个干预之后各判据是否通过
result.flips()    # 哪些判据翻转
```

支持的原子操作：

| op | 参数 | 含义 |
|---|---|---|
| `material` | `material`、`top_depth`、`bottom_depth`、`model` | 换填 / 改良 |
| `elevation` | `delta` 或 `absolute` | 开挖 / 填方 |
| `water_table` | `depth` | 降水 / 排水 |
| `precip` | `factor` 或 `absolute` | 气候情景 |
| `pft` | `pft`、`mode`（replace/seed） | 植被替换 |
| `gravity` | `value` | 换天体 |

**选址与干预必须对齐**：判据永远在 `Criteria` 指定的场地评估。干预区与验证点不重叠时结论不会变——这是刻意的，避免"改哪就在哪通过"。

## 6. 不确定性

```python
from blockworld import Distribution, Parameter, monte_carlo, morris

params = [
    Parameter("软黏土 c", {"kind": "material_prop", "material": "clay_soft", "prop": "c"},
              Distribution("uniform", 8, 40)),
    Parameter("足垫直径", {"kind": "lander", "field": "pad_diameter"},
              Distribution("uniform", 0.2, 0.9)),
]

mc = monte_carlo(study, params, n=200, seed=1, intervention=study.interventions[0])
mc.baseline["infrastructure"]["p_fail"]      # 基线失效概率
mc.intervention["infrastructure"]["p_fail"]  # 干预后失效概率

mr = morris(study, params, r=6, seed=1, intervention=study.interventions[0])
mr.ranking("landing")                        # 按 mu* 排序，谁在主导结论
```

| 输出字段 | 含义 |
|---|---|
| `p_fail` | 该判据失效的样本比例 |
| `margin_p05/p50/p95` | 裕度分位数，负值即失效 |
| `mu` | 初等效应均值（方向） |
| `mu_star` | 初等效应绝对均值（影响强度，排序用） |
| `sigma` | 初等效应标准差（非线性或交互强） |

为什么不用秩相关：确定性、单调的单点扫描下 Spearman 必然饱和到 ±1，没有信息量。

## 7. 机器人在环

### 7.1 环路

```text
终端(载荷) ──测量(带σ)──► 同化器 ──► 孪生模型 ──► 判据 ──► 决策
   ▲                    逆方差融合      │                    │
   │                    4σ 异常门控      │                    ▼
   └──── 链路 loopback/JSONL/TCP ────────┘      复扫/处理/中止/升级/认证
```

### 7.2 三个替换点

| 想换什么 | 接口 | 说明 |
|---|---|---|
| 传感器载荷 | `register_device(name, factory)` | LiDAR → GPR → 探针 → 你的 SDK |
| 链路 | `register_transport(name, factory)` | 进程内 / JSONL 录制回放 / TCP |
| 判断策略 | `Supervisor` / `PolicyConfig` | 阈值与规则 |

### 7.3 同化规则

1. 逆方差融合：`w = σ_prior² / (σ_prior² + σ_meas²)`；
2. 4σ 门控：`|x − 先验| / √(σ_p² + σ_m²) > 4` 直接拒绝并记录；
3. 点测只改一个区块（高程、水位），**不做邻域平滑**——那会把坡面抹平；
4. 强度测量按距离高斯衰减扩散，因为岩性单元横向连续；
5. 扫描报告的材料在柱内不存在时执行**重分类**（替换该深度层），而不是微调参数。

### 7.4 判断规则

| 顺序 | 条件 | 动作 |
|---|---|---|
| 1 | 有效测量 < 12 或地下证据覆盖 < 90% | `rescan` |
| 2 | 失效概率超过上限 | `treat`（有方案）/ `abort` |
| 3 | 判据不通过且有方案 | `treat` |
| 4 | 判据不通过且无方案 | `abort` |
| 5 | 裕度低于认证线且复扫无变化 | `escalate`（转人工） |
| 6 | 通过且裕度 ≥ 认证线 | `certify` |

默认阈值：`certify_margin=0.30`、`min_evidence=12`、`min_coverage=0.90`、`p_fail_limit=0.50`。

### 7.5 覆盖率口径

覆盖率只统计**地下证据**（强度、水位）。只测高程不能认证承载力——这是刻意设计，
因为高程测量对沉降与承载判据几乎不提供信息。

### 7.6 执行与真值同步

`act=True` 时，判定 `treat` 会把干预同时写入孪生模型**和真值世界**。否则下一轮
传感器读到未处理的地层，会把手做的处理"同化"回去，表现为"执行后判据又掉回去"。

### 7.7 接入真实硬件

```python
from blockworld.robot import Measurement, register_device

class MyCPT:
    name = "cpt-live"

    def __init__(self, port):
        self.link = open_serial(port)

    def scan(self, truth, rng):          # 真实硬件上 truth 用不到
        frame = self.link.readline()     # {"depth": 1.2, "qc": 1.8}
        return [Measurement("material_c", x=self.x, y=self.y,
                            value=qc_to_c(frame["qc"]), sigma=2.0,
                            depth=frame["depth"], material="clay_soft",
                            device=self.name)]

register_device("cpt-live", MyCPT)
```

一个适配器约 15 行；链路同理，实现 `send/recv` 后注册为 `tcp:`。

## 8. 离线 AI 顾问

### 8.0 不依赖任何平台

接入方式是**直接 HTTP**：没有厂商 SDK、没有账号、没有云端调用点，也没有 API Key
流程。只要有一个端点，说话像下面任意一种即可：

| 端点协议 | 用法 |
|---|---|
| Ollama 原生 | `--backend ollama` |
| OpenAI 兼容（llama.cpp / vLLM / LM Studio / SGLang / 自己写的 30 行 Flask） | `--backend openai` |
| 都不是 | 实现 `LLMClient`（`available()` + `chat()`）后 `register_client()` 注册 |

部署时不必改代码，用环境变量配置即可；命令行参数优先级最高：

```bash
export BLOCKWORLD_LLM_BACKEND=openai
export BLOCKWORLD_LLM_BASE_URL=http://10.0.0.5:8080/v1
export BLOCKWORLD_LLM_MODEL=local-7b
export BLOCKWORLD_LLM_API_KEY=offline        # 本地端点通常随便填
export BLOCKWORLD_LLM_TIMEOUT=120
blockworld agent --out out_agent
```

优先级：命令行参数 → 环境变量 → 内置默认值（`ollama` / `127.0.0.1:11434` /
`qwen2.5:7b`）。`--list-models` 会打印当前后端、模型、可用性与接入方式，便于现场确认。

### 8.1 三个后端

| 后端 | 端点 | 说明 |
|---|---|---|
| `ollama` | `POST /api/chat` | `format: json` 强制结构化输出；`/api/tags` 健康检查 |
| `openai` | `POST /v1/chat/completions` | llama.cpp server、vLLM、LM Studio |
| `none` | — | 永不联网，强制走确定性回退 |

```bash
blockworld agent --out out_agent --model qwen2.5:7b
blockworld agent --backend openai --base-url http://127.0.0.1:8080/v1 --model local
blockworld agent --backend none
blockworld agent --list-models
```

### 8.2 三条硬约束

1. **没有否决权**：`Advice.advisory_only` 恒为 True，报告对象不被修改；
2. **分歧留痕**：模型 verdict 与策略不一致时，`agrees_with_policy=False`，前置一条
   caveat，简报同时打印两者并标注以策略为准；
3. **永远有产出**：模型不可用、超时、输出非 JSON，都回退到同一份事实的确定性摘要，
   `source` 标记 `fallback(...)`。

### 8.3 事实包字段

判据与裕度、先验 vs 最终、覆盖率、逐 tick 时间线（含处理与是否执行）、模型黏聚力
与摩擦角误差、策略阈值。不含原始测量流，几 KB，7B 模型可完整吃下。

### 8.4 简报结构

结论 → 场景 → 判据对照表 → 闭环时间线 → 处置 → 模型修正 → 风险 → 建议 →
前提与数据缺口 → 声明。

### 8.5 没有本地模型时

`tools/fake_ollama.py` 提供两个端点、返回固定 JSON，用来验证链路与解析：

```bash
python tools/fake_ollama.py --port 11500
blockworld agent --base-url http://127.0.0.1:11500 --model qwen2.5:7b
```

它不做任何推理，只验证接线。

### 8.6 选型建议

| 模型 | 说明 |
|---|---|
| `qwen2.5:7b` | 中文好，稳定遵循 JSON 契约 |
| `llama3.1:8b` | 可用，偶尔把 JSON 包在叙述里（解析器能处理） |
| `qwen2.5:1.5b` | 能跑，但 caveats 偏泛，只适合兜底质量 |

## 9. 判据与公式

| 判据 | 模型 | 失效条件 |
|---|---|---|
| 基础设施 | `qu = c·Nc·sc·dc + q·Nq·sq·dq + ½·γ·B·Nγ·sγ·dγ`，`FS = qu / q_applied` | `FS < 3`，或沉降 > 25 mm，或坡度 > 20° |
| 边坡 | `FS = [c + (γz·cos²β − u)·tanφ] / (γz·sinβ·cosβ)` | 最不利坡面 `FS < 1.3` |
| 着陆 | 足垫压力 `p = m·g/(n·A)`，动力放大 `1 + a/g`，与 `qu` 比较 | `FS < 2`，或穿透 > 半个缓冲行程，或减速度超限 |
| 生态 | 植被覆盖、群区多样性、动物种群 | 覆盖 < 60%，或群区 < 2，或动物群落不可持续 |

`margin` 是各子判据归一化裕度的最小值：`≥ 0` 即通过。`flip` 表示基线与干预之间
通过状态的改变。

单位约定：长度米、应力 kPa、重度 kN/m³、模量 MPa、能量 kJ、质量 kg、时间年。

## 11. 排错

| 报错 | 原因 | 处理 |
|---|---|---|
| `缺少 DEM 高程` | `SiteSpec.elevation` 为空 | 提供 DEM，或改用 `synthesize()` 生成示例 |
| `DEM 形状 (ny,nx) 与网格不符` | 行列颠倒或尺寸错 | 转置矩阵或改 `grid.nx/ny` |
| `SiteFormatError: ... 有缺失层` | 钻孔区间不连续 | 补齐区间，从 0 开始 |
| `DomainError: 材料 ... 不支持本构` | 材料与本构不匹配 | 换材料或换 `model` |
| `EnvelopeError` | PFT 气候包络外 | 换 PFT，或检查气温/降水场 |
| `JSONDecodeError: Unexpected UTF-8 BOM` | 编辑器写了 BOM | 已用 `utf-8-sig` 读取；旧文件可用无 BOM 保存 |
| `KeyError: 未知终端/链路/后端` | 名字拼错 | 见 `device_table()` / `TRANSPORTS` / `CLIENTS` |
| `UnicodeEncodeError`（Windows 控制台） | 控制台非 UTF-8 | 已自动重配 stdout；如仍出现，设 `PYTHONIOENCODING=utf-8` |
| 判据始终不变 | 干预区与验证点不重叠 | 固定 `foundation_site` / `landing_site` |

## 12. 可信度与边界

四类数值，必须分清：

| 类别 | 含义 | 可信度 |
|---|---|---|
| 推导 | 由代码中写明的公式得到 | 高，可逐项验算 |
| 引用 | 文献经验系数，按量级使用 | 中，量级对、非场地标定 |
| 假设 | 为使模型行为合理而选的数 | 低，只可用于相对比较 |
| 合成 | `synthesize()` 生成的示例 | 无，不能作为场地证据 |

因此：**用于同场地方案 A 与 B 的比较**；不要报"该场地承载力是 X kPa"。

合成场地的"重建精度"是真值与采样同源的自证循环，仅作程序自洽性诊断。

## 13. 二次开发

| 想替换 | 调用 |
|---|---|
| 承载力/沉降公式 | `solvers.register_property("bearing_qu", fn)` |
| 整条判据 | `solvers.register_criterion("landing", fn)` |
| 传感器 | `robot.register_device("my-cpt", Factory)` |
| 链路 | `robot.register_transport("tcp", Factory)` |
| 模型后端 | `agent.register_client("my-rig", Factory)` |

外部求解器约定：`bearing_qu` 接收字典
`{c, phi, gamma, B, D, shape, L, gravity}`，返回 `float` 或含 `qu_kpa` 的字典；
注册情况会写进结果的 `meta.solvers`，便于追溯结论由谁算出。
